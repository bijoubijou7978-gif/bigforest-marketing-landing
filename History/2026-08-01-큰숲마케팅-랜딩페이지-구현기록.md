# 큰숲 마케팅 랜딩페이지 구현 기록

## 승인된 브리프

- 큰숲 마케팅의 개정 PRD v1.1과 제공받은 브랜드 키트를 기반으로, 로컬 반응형 랜딩페이지를 구현한다.
- 배포와 GitHub 게시를 제외하고 로컬 미리보기와 검증까지 수행한다.

## 적용 결정

- 공식 색상은 Forest Deep Green `#0D3B2E`, Trust Navy `#142B4D`, Growth Gold `#D4A62A`, Charcoal `#222222`, Solid White `#FFFFFF`를 사용한다.
- 제공 로고 파일의 색상과 비율은 수정하지 않고 프로젝트 자산으로 복사해 사용한다.
- 숲의 수직 구조와 상승 곡선을 CSS 그래픽으로 재해석해 Hero에 적용한다.
- 실제 고객사·후기·성과가 없으므로 사례 영역은 `진단 예시 · 실제 사례 아님`으로 명시한다.
- 전화·카카오·폼 API·개인정보처리방침·사업자 정보가 제공되지 않아, 사용자에게 오인되지 않는 안내와 배포 전 교체 항목으로 표시한다.

- 실행 명령: `python -m http.server 4173 --bind 127.0.0.1`
- 로컬 URL: `http://127.0.0.1:4173/2026-08-01-큰숲마케팅-랜딩페이지.html`
- 데스크톱 DOM·레이아웃 확인 완료. Hero, 섹션 앵커, 상담 폼, FAQ, 푸터가 정상적으로 표시됨.
- 375px 모바일에서 Hero, 헤더 메뉴, 하단 고정 CTA가 표시됨. 메뉴 버튼 클릭 시 `aria-expanded=true`, 내비게이션은 `display:flex` 상태로 전환됨.
- FAQ “성과를 보장하나요?” 클릭 시 열림 상태가 `aria-expanded=true`로 전환됨.
- 빈 폼 제출 시 “필수 입력값, 연락처 형식, 개인정보 동의를 확인해주세요.”라는 검증 안내가 표시됨.
- 브라우저 오류 로그 0건 확인.

## 2026-08-01 — 인터랙션 보강

- 승인 요청: “엑티비티효과를 좀 넣었으면 좋겠어.”
- Hero에 성장 막대 순차 등장, 골드 상승 곡선 전개, 은은한 광원 이동을 추가했다.
- 각 섹션은 화면 진입 시 위로 부드럽게 등장하고, 서비스 카드는 마우스 오버 시 떠오르며 아이콘이 반응한다.
- CTA에는 가벼운 상승·그림자 반응을 적용했다.
- `prefers-reduced-motion`에서는 모든 자동 모션을 해제하고 콘텐츠를 즉시 표시한다.

## 2026-08-01 — 고은마케팅 레퍼런스 반영

- 참고 URL: `https://goeunm.com/`
- 반영: 고객이 검색 의도에서 상담·방문까지 이동하는 흐름을 설명하는 `고객 여정` 섹션을 추가했다. 채널 나열보다 고객의 다음 행동을 설계한다는 큰숲의 기존 포지션을 강화한다.
- 반영: 상담 폼에 선택형 `관심 있는 영역` 항목과 500자 제한을 추가해 상담 맥락을 더 쉽게 전달할 수 있게 했다.
- 미반영: 외부 사이트의 고유 문구, 이미지, 대표 직접 관리 주장, 실적·재계약률·포트폴리오 수치. 큰숲에 제공되거나 검증된 근거가 없기 때문이다.

## 2026-08-01 — 실제 포트폴리오 및 운영 지표 반영

- 사용자 제공 자료를 큰숲의 실제 수행 이력으로 확인하고, 예시 포트폴리오 영역을 실제 8개 업종 사례로 교체했다.
- 운영 이력 지표: 대표 직접 기획 100%, 클라이언트 재계약률 90%+, 누적 작업 632건, 매출 증가 사례 584건.
- 방충망 업체의 예약률 200% 상승 전략을 포함해 제공된 포트폴리오 캡션을 반영했다.
- 개별 프로젝트의 공개 범위는 고객 승인 기준을 따른다는 안내를 추가했다.

## 2026-08-01 — 운영 지표 카운트업 효과

- `100%`, `90%+`, `632건`, `584건`은 포트폴리오 지표 영역이 화면에 들어올 때 1회에 한해 1.5초 동안 카운트업한다.
- 퍼센트·플러스·건 단위는 숫자 변화 중에도 유지한다.
- `prefers-reduced-motion` 환경에서는 숫자를 즉시 최종값으로 표시한다.

## 2026-08-01 — 포트폴리오 색상 포인트 보강

- 네이비 배경은 유지하되, 운영 지표마다 딥그린·블루·골드 글로우를 분산했다.
- 실제 업종 포트폴리오 카드는 브랜드 팔레트에서 파생한 딥그린·블루·골드 계열의 그라데이션으로 구분했다.
- 카드 오버 시 골드 테두리와 은은한 원형 그래픽이 반응하도록 적용했다.

## 2026-08-01 — 상담 채널 및 Supabase DB 연결 준비

- 전화 CTA를 `tel:01065423522`로, 카카오 CTA를 제공된 오픈채팅 URL로 연결했다.
- 상담 폼은 Supabase 프로젝트 `amvgpkowbaqwsvrzvgos`의 `consultations` 테이블에 INSERT하도록 구성했다.
- 브라우저에는 publishable key만 사용하고, 읽기·수정·삭제 권한은 부여하지 않는 RLS SQL 스키마를 별도 파일로 제공했다.
- 폼에는 숨김 honeypot 필드를 추가해 기본적인 자동 제출 방어를 적용했다.
- 원격 테이블 생성은 대시보드 SQL Editor 권한이 필요한 작업으로, 스키마 실행 후 실제 데이터 저장을 확인해야 한다.
- 푸터에도 전화번호와 카카오톡 상담 링크를 노출하고, 남은 배포 필수 항목은 개인정보처리방침과 사업자 정보로 명확히 표시했다.

## 2026-08-01 — 기존 consultations 테이블 매핑

- 사용자가 조회한 기존 테이블 컬럼은 `id`, `created_at`, `company`, `name`, `phone`, `concern`, `place`, `services`다.
- 랜딩 폼 payload를 이 구조에 맞춰 수정했다. 지역은 `place`, 업종·관심 영역·상담 방식을 `services` 배열로 저장한다.
- 이전에 생성한 신규 테이블 SQL 파일은 실행하지 않도록 안내용 메모로 전환했다.
- 실제 공개 전에는 기존 테이블의 anon INSERT RLS 정책 존재 여부를 읽기 전용 쿼리로 확인해야 한다.

## 2026-08-01 — 상담 접수 완료 모달

- Supabase 저장 응답이 성공일 때만 완료 모달을 연다.
- 모달에는 접수 확인과 순차 연락 안내를 표시하며, 확인 버튼·닫기 버튼·배경 클릭·Escape 키로 닫을 수 있다.
- 접수 실패 시에는 모달을 열지 않고 기존의 전화·카카오 대체 안내를 표시한다.
- 배포 전에는 실제 폼 API, 전화번호, 카카오톡 링크, 개인정보처리방침, 사업자 정보를 연결해야 한다.
